# Независимая оценка всех типов

```sh
make test-anomalies
```

Команда проверяет 18 типов минутных находок, пять типов сервисных аномалий, общий сигнал Isolation Forest и сигнал GRU. Она запускает те же функции прогнозирования и классификации, которые вызывает сервис. Единица оценки для минутных правил — одно минутное наблюдение, для моделей — одно пятисекундное окно. Для GRU требуются 12 предыдущих окон в той же непрерывной серии.

Отчёт сохраняется в `outputs/anomaly-holdout.json`. Для каждого типа нужны размеченный положительный пример и размеченный отрицательный контроль. Команда возвращает ненулевой код при отсутствии набора, пересечении источников, неполном покрытии, пропуске, ложном срабатывании или невозможности оценки. В отчёте есть счётчики и результат каждого случая.

## Подготовка отложенного набора

Хранитель данных готовит `data/holdout/anomalies/manifest.json`, исходные записи и размеченные входы. Каталог исключён из Git. По умолчанию используются локальные пакеты моделей `artifacts/tcp-service-patterns-v2` и `artifacts/step10-gru` и исходный манифест `data/processed/step7-16d38550a4d3/manifest.json`. Для других путей есть переменные Makefile `ANOMALY_MANIFEST`, `ANOMALY_SERVICE`, `ANOMALY_FORECAST`, `ANOMALY_TRAINING` и `ANOMALY_REPORT`.

- Отложите целые записи до подбора порогов и обучения. Разные фрагменты одной записи, повторное декодирование и другая точка наблюдения того же эпизода относятся к одной группе. Сохраните исходные PCAP или журналы для проверки происхождения.
- Заполните `development_groups` для дополнительных записей, которые использовались при разработке, обучении, валидации, калибровке или при предыдущих оценках. Включите исходные SHA-256 и стабильные ID групп. Скрипт также исключает источники из манифеста обучения, известные записи настройки и ранее разобранный внешний набор.
- Зафиксируйте версии правил и моделей до открытия отложенной выборки. Разметку должен устанавливать источник истины независимо от NetWatch. Лишь затем хранитель подтверждает `unseen_by_developers`. Сверка хешей выявляет совпадение файлов. Происхождение переработанных копий устанавливается по группам и исходным записям. При изменении детектора по итогам разбора используйте для подтверждения качества новый отложенный набор.

Поля манифеста показаны ниже. Это описание структуры с условными значениями. Полный набор должен содержать все типы из таблицы, которую печатает цель.

```json
{
  "version": 1,
  "unseen_by_developers": true,
  "models": {"service": "<SHA-256 bundle.json>", "forecast": "<SHA-256 bundle.json>"},
  "passive_sha256": {
    "ml/netwatch_ml/security.py": "<SHA-256>",
    "contracts/security-observation.schema.json": "<SHA-256>"
  },
  "development_groups": [{"id": "earlier-capture", "sha256": ["<SHA-256>"]}],
  "holdout_groups": [
    {"id": "new-capture", "sources": [{"path": "raw/trace.pcap", "sha256": "<SHA-256>"}]}
  ],
  "cases": [
    {
      "id": "new-capture-minute-7",
      "group": "new-capture",
      "kind": "passive",
      "input": {"path": "inputs/minute-7.json", "sha256": "<SHA-256>"},
      "expect": {"port_scan": true}
    }
  ]
}
```

`passive` принимает JSON по схеме `contracts/security-observation.schema.json`, полученный из записи или журнала. `service` принимает JSON с полем `window`, соответствующим `contracts/window.schema.json`. Получайте эти окна штатным Go-сенсором. `forecast` принимает тот же `window` и массив `history` со строго предшествующими окнами. В `expect` указывайте `true` для размеченной аномалии и `false` для подтверждённого отсутствия этого типа. Классы без разметки в данном случае пропускаются. Путь каждого файла задаётся относительно манифеста и проверяется по SHA-256.

Таблица известных [внешних записей](external-evaluation.md) воспроизводит предыдущий эксперимент. Эти записи уже анализировались при настройке passive-v2 и исключены из строгого прогона.
