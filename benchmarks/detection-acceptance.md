# Независимая приёмка детектора

`make test-e2e` запускает отдельный экземпляр серверного Compose с временной
БД и сертификатом. Проверка включает запись прогноза, HTTPS, контроль доступа,
приём минутного наблюдения при остановленном Python и обработку после его
возвращения. Модель берётся из `E2E_ARTIFACT`.

`make test-acceptance` требует зафиксированный манифест. По умолчанию он
ожидается в `data/holdout/detection/manifest.json`. Путь можно указать через
`ACCEPTANCE_MANIFEST`. Отчёт по умолчанию сохраняется в
`outputs/detection-acceptance.json`. В случае отсутствия манифеста, ошибки
проверки или невыполнения порогов команда возвращает ненулевой код.

## Состав манифеста

- `version` равно 1. `unseen_by_developers` подтверждает, что эти записи были
  отложены до сравнения моделей и настройки порогов.
- `model_sha256` фиксирует проверяемый `bundle.json`. `training_manifest`
  содержит `path` и `sha256` зафиксированного манифеста обучения. Скрипт сверяет
  его с происхождением модели.
- `policy_version` выбирает проекцию инцидентов `v1` или `v2`. При отсутствии
  поля применяется `v1` для совместимости с зафиксированными экспериментами.
- `development_groups` содержит группы использованных данных с `id` и
  массивом хешей `sha256`.
- `limits` фиксируется до раскрытия теста. Поля `min_recall`,
  `max_false_per_hour`, `max_start_error_s`, `max_end_error_s`,
  `min_normal_hours` и `min_evaluated_fraction` задают допуски.
- `cases` содержит отдельные группы наблюдений. В каждой группе есть `id`,
  список оригинальных `sources` с `path` и `sha256`, ссылка `windows`
  с `path` и `sha256`, а также списки `normal` и `anomalous`.
  Каждая метка задаёт пару времён Unix в наносекундах. Интервалы не
  пересекаются и лежат внутри записи. Файл окон содержит JSONL, полученный
  Go-сенсором, с непрерывными пятисекундными окнами одного сервиса.
  Пути задаются относительно каталога манифеста.

Скрипт исключает точные совпадения исходников с данными обучения, известными
архивными источниками и локальными манифестами предыдущих испытаний.
Происхождение переупакованных копий подтверждается на этапе подготовки
манифеста. Приёмка отправляет окна в штатный API Compose, ждёт обработку и
сопоставляет интервалы из журнала с разметкой. Эпизоды сопоставляются один к
одному по пересечению и времени открытия внутри размеченного интервала.
Для профилей с привязкой сохраняются идентификаторы сенсора, эпохи и окон.
Приёмка поддерживает манифесты `train/profiled` и оба набора признаков.
Ошибка конца считается по `estimated_end_ns`, а окончание без
подтверждения отмечается отдельно. В отчёте также видны покрытие оценки,
дробление и слияние эпизодов, а также причины недоступной оценки. Дробление и слияние проверяются
по пересечению интервалов и блокируют выпуск. Ложные тревоги считаются по
времени подтверждения инцидента. В длительность нормы входят только
размеченные интервалы, в которых детектор действительно выдал решение.

Лабораторный сравнительный прогон приведён в [отчёте](detection-results.md).
