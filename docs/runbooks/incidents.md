# Журнал инцидентов

## Открыть журнал

Подготовьте PostgreSQL и окружение API по [инструкции сервера](server.md).
Для своего датасета обучите модель и укажите путь к комплекту, SHA-256 и ID
по [инструкции детектора](detector.md). Запустите ML и worker с этим окружением.
В терминале API, перед запуском сервера, выполните команды из корня проекта.

```sh
make build
make migrate
export NETWATCH_WEB_DIR="$PWD/web/dist"
export NETWATCH_OPERATOR_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
export NETWATCH_OPERATOR_TOKENS="$(python3 -c 'import json, os; print(json.dumps({"operator":os.environ["NETWATCH_OPERATOR_TOKEN"]}))')"
make api
```

Откройте http://127.0.0.1:8080/ и введите значение NETWATCH_OPERATOR_TOKEN.
API раздаёт собранный интерфейс с того же адреса. Оператор видит все сенсоры.
Сервер определяет имя подтверждающего по ключу. Браузер держит ключ в памяти
вкладки до выхода или перезагрузки. Для постоянной установки задайте отдельные
секреты операторов в окружении сервиса.

## Прочитать карточку

Worker ведёт отдельное состояние для каждого сочетания сенсора, эпохи захвата,
объекта, модели и политики. Два превышения порога среди трёх последовательных
валидных окон открывают инцидент. Следующие превышения пополняют его историю.
Три последовательных нормальных окна с оценкой не выше 95 % своего порога
закрывают инцидент. Пропуск или недоступная оценка прерывают серию. Запоздалый
результат за уже обработанный интервал сохраняется в прогнозах, история остаётся
в прежнем виде. При остановке сенсора открытая запись ждёт следующих наблюдений.

Нажмите «Обновить», выберите запись и сравните числа пакетов с оценкой и порогом
в тех же окнах. Полоса показывает сумму входящих и исходящих пакетов относительно
максимума загруженных окон. Время в журнале указано в UTC. Фильтры работают по
точному объекту, идентификатору модели и моменту обнаружения в интервале [с, до).
Индикаторы очереди относятся ко всем потокам. Подтверждение сохраняет первого
оператора и время просмотра. Экспорт JSON включает всю доступную историю,
признаки, качество наблюдения, прогноз, версии и дату выгрузки. Для открытого
инцидента история может пополняться между запросами страниц.

## Повторить сквозную проверку

После make bootstrap и make build понадобятся Docker, установленный Google Chrome
и обученный локальный комплект с bundle.json и report.json. Из корня проекта
передайте каталог своего комплекта.

```sh
ml/.venv/bin/python scripts/incident_smoke.py "$ARTIFACT"
```

Сценарий выполняет 90-секундный обмен в изолированном сетевом стенде с паузой,
передаёт записанные окна через очередь сенсора в отдельную БД, запускает worker
и ML. Проверка требует закрытого инцидента, который пересекается с записанной
паузой. Chrome открывает карточку, подтверждает просмотр и проверяет JSON.
После перезапуска PostgreSQL, ML, API и worker сценарий сравнивает историю.
Для повторения на той же записи добавьте `--run путь/к/запуску` с файлами
live.jsonl и truth.json. Исходные записи остаются локально. Завершение теста
подтверждает работу цепочки на этом сценарии. Качество модели оценивается
отдельно на отложенных группах.
