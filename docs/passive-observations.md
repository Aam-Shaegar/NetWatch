# Нагрузка, доступность и признаки атак

Пятисекундный детектор TCP-сервиса продолжает работать через обычный журнал инцидентов. Для дополнительных источников есть отдельный классификатор. Он принимает одну проверенную минуту наблюдений за одним объектом. Результат доступен в CLI или через внутренний POST /v1/security/assess; для доставки в журнал используйте одноимённый маршрут Go API с ключом сенсора. Параметр CLI `--journal http://127.0.0.1:8080` указывается перед подкомандой. Нужна переменная NETWATCH_SENSOR_TOKEN. Без параметра CLI выполняет локальный расчёт. Go API обращается к внутреннему ML по NETWATCH_SECURITY_ENDPOINT (по умолчанию http://127.0.0.1:8000/v1/security/assess), сохраняет исходные метрики, правила, находки и пропуски оценки. Повторная отправка того же наблюдения тем же сенсором с той же версией правил возвращает прежний ID. В журнале откройте «Минутные наблюдения».

Из корня NetWatch запустите:

    ./scripts/uv run --project ml python -m netwatch_ml.security_import observation minute.json

Пример содержимого minute.json:

    {"schema_version":1,"entity":"lab-web","start_s":0,"interval_s":60,"metrics":{"in_pps":150,"pps_baseline_ratio":6,"source_ips":20}}

Результат содержит `packet_flood` с типом `traffic_pattern` и `availability: unmeasured`. Поле `unassessed` перечисляет правила, для которых не хватило измерений. Несколько сигналов могут относиться к одному эпизоду. Оператор видит отдельно нагрузку, доступность по пробам, признаки безопасности и сигналы внешнего WAF.

| Тип сигнала | Как читать |
|---|---|
| `traffic_pattern` | Всплеск общего, протокольного или HTTP-трафика |
| `degradation_pattern` | Перегрузка с измеренными отказами. Коды `dos`, `ddos` и `web_ddos` обозначают наблюдаемый рисунок, у которого могут быть разные причины |
| `security_indicator` | Совпадение по признакам безопасности, например серия отказов для одной учётной записи |
| `waf_signal` | Внешний WAF отметил транзакцию |

Go измеряет сеть и доступность, проверяет контракты на входе API и записывает наблюдение с решением Python. Python нормализует прикладные журналы, оценивает нагрузку и применяет отдельные правила корреляции. Статистическая аномалия сервиса и результаты наблюдательного GRU не переводятся в метки атак. GRU не открывает и не переоткрывает инциденты.

| Источник | Какие признаки можно различить |
|---|---|
| Входящие пакеты и обычная нагрузка того же узла | Рост числа портов у одного источника, высокая частота пакетов, преобладание UDP или ICMP при всплеске |
| Пакеты и независимые пробы доступности | Перегрузка с отказами; множество видимых источников добавляет метку распределённой перегрузки |
| Счётчики рукопожатий TCP | Рост SYN при низкой доле завершений |
| Журнал HTTP-сервера | Распределённый всплеск с ошибками; длительное ожидание незавершённых заголовков с тайм-аутами |
| Журнал входов | Многократные отказы для одной учётной записи |
| ModSecurity с OWASP CRS | Сообщение WAF о признаках SQLi или XSS |
| Контроль передачи данных и политика назначения | Передача чувствительных данных за разрешённую границу |
| События процессов, связанные с запросом | Нарушение политики запуска процесса; возможная эксплуатация |
| Входной фильтр, монитор шлюза и проверка TLS | Нарушение политики адреса источника; смена шлюза вместе с несовпадением TLS-ключа |
| Журналы DNS и исходящих соединений | Возможный DNS-туннель по характеру имён; периодические соединения с неодобренным адресом |

## Подключение данных

Команда packets принимает два файла метаданных отдельных пакетов от Go-сенсора (replay без параметров хоста и сервиса). Укажите IP назначения, начала полной текущей и обычной минуты в секундах Unix:

    ./scripts/uv run --project ml python -m netwatch_ml.security_import packets current.jsonl --reference ordinary.jsonl --entity 192.0.2.10 --start 120 --reference-start 0 --complete-minutes

Флаг подтверждает проверку оператором длительности и отсутствия потерь, а не выполняет эту проверку. Нулевой знаменатель не заменяется единицей. Для режима waf вход — один JSON-аудит ModSecurity; --entity и --start оператор берёт из контекста этой транзакции. Результат относится к сообщениям одной транзакции.

Режимы auth, dns и egress читают JSONL (одна запись на событие). Нужны --entity, --start и --complete-minute. Обязательны время time_s в секундах Unix и entity. Для auth добавьте principal и логический success; для dns — qname и логический unapproved_destination; для egress — unapproved_destination и одну запись на начало исходящего соединения. В DNS-группе entity обозначает одну пару клиент/родительский домен, в egress — клиент/точное назначение. Метка неодобренного назначения поступает из вашей политики. Пример строки журнала входов:

    {"time_s":123,"entity":"lab-web","principal":"demo","success":false}

Для остальных источников передавайте сводку по [схеме](../contracts/security-observation.schema.json). Доли задаются от 0 до 1, отношения к обычной минуте — как множители, unavailable_fraction — доля неуспешных независимых проверок доступности. Пропускайте неизвестные значения. Измерения, относящиеся к разным узлам, запросам или периодам, нельзя объединять ради срабатывания.

[Пороговые правила](../ml/netwatch_ml/security.py) описывают наблюдаемое сочетание признаков. Это начальные пороги, не оценка вероятности атаки. Законная нагрузка может вызвать тот же сигнал; отсутствие сигнала не исключает атаку. CLI не устанавливает WAF, монитор процессов или датчик утечек. Для оценки точности нужны независимые размеченные эпизоды, обычная нагрузка и частота ложных инцидентов за час.

## Эталон для всплесков и история входов

В режиме packets добавьте `--reference-minutes 5`, чтобы прочитать пять полных нормальных минут от `--reference-start` на том же интерфейсе. Допустимый диапазон — от 1 до 60. Оператор должен подтвердить покрытие всего эталонного интервала. Измеренный нулевой трафик и отсутствие наблюдения различаются. Исходный режим с одной минутой сохраняет прежнюю проверку отношения к норме.

При пяти и более минутах правила passive-v2 сравнивают текущее значение с медианой обычных минут плюс большим из двух значений: медианы и шести медианных абсолютных отклонений. Абсолютные требования к интенсивности сохраняются. Для короткого всплеска вычисляется максимум скорости в пятисекундных отрезках текущей минуты. Для UDP и ICMP учитывается скорость соответствующего протокола в отрезке с долей этого протокола не менее 80%. Она должна превысить как обычный протокольный максимум, так и границу общего трафика. Сигнал выдаётся после закрытия минуты.

Для режима auth ключ `--auth-history` включает в анализ предыдущие четыре минуты журнала вместе с текущей. Проверяются аккаунты, по которым в текущей минуте зарегистрирован отказ. Суммировать события разных пользователей для достижения порога нельзя. Для определения SYN-попыток нужны TCP-флаги, номера последовательности и подтверждения из метаданных Go-сенсора и оба направления соединения.

Для попыток TCP у конца минуты импортёр принимает подтверждения из первых пяти секунд следующей минуты, если они присутствуют во входном файле. Счётчик относится к минуте начала. Если наблюдение завершается на незакрытой попытке в последние пять секунд, доля завершений остаётся неизвестной. При неполном TCP-заголовке правило также может остаться без оценки. Пятисекундные пики отсчитываются от начала проверяемого интервала.

### Сводки нескольких наблюдателей

Для сигналов, требующих корреляции, используйте импорт `telemetry`. Доверенный сборщик экспортирует JSONL. Каждая строка содержит `entity`, `start_s`, `cohort`, `source`, `coverage`, `expected_change`, `policy_valid_until_s` и `metrics`. Все строки относятся к одному сервису, минуте и когорте. Импорт отклоняет несовпадающие или дублирующиеся источники. В отчёт входят метрики источников с полным покрытием.

Для DoS/DDoS нужны `network`, `probe` и `change`. Для признаков HTTP DDoS нужны `http`, `probe` и `change`. Для медленных заголовков, вывода данных и связи запроса с процессом нужны `headers`, `dlp` и `process` соответственно. Для подмены источника нужны `ingress` и `change`. Для возможного MITM нужны `gateway`, `tls` и `change`. Сборщики передают измеренные величины и срок действия актуальной политики. Поле `expected_change` от наблюдателя `change` подтверждает заранее запланированное событие для этой когорты. Во время такого события журнал продолжает показывать нагрузку и отказы проб. При неполных данных потенциальные совпадения правил остаются без оценки.

Для `dns` и `egress` параметр `--history-minutes` принимает 1, 5 или 15 полных минут. История относится к одному клиенту и назначению. Она учитывается при наличии события в текущей минуте и согласованной политике назначения. Сигнал всплеска на фоне подтверждённой тишины получает отдельное основание. Совпадения CRS отображаются как сигналы WAF.

### Замеры доступности и HTTP-журнал

Go-проба делает четыре GET-запроса к заданному endpoint на 5-й, 20-й, 35-й и 50-й секундах. Тайм-аут составляет три секунды. Статусы 2xx считаются успешными, перенаправления учитываются как отказы. Запускайте пробу из отдельной точки сети. Задайте `START` началом ближайшей минуты, `EXPIRES` сроком актуальности конфигурации, `HEALTH_URL` адресом проверяемой службы.

    go run ./cmd/netwatch-probe -url "$HEALTH_URL" -entity lab-web -cohort ingress-a -start "$START" -policy-valid-until "$EXPIRES" > probe.json
    ./scripts/uv run --project ml python -m netwatch_ml.security_import probe-log probe.json > probe.jsonl

Команда `probe-log` преобразует JSON с `entity`, `cohort`, `start_s`, `policy_valid_until_s`, `schedule` и `results` в строку наблюдателя `probe` для импорта `telemetry`. Каждый элемент расписания задаёт `id` и `time_s`. Измеренный результат содержит те же `id`, `entity`, `cohort`, фактический `time_s` завершения и логическое `available`. Доля отказов вычисляется при наличии всех запланированных измерений за минуту. Пропуск образца отмечается как неполное покрытие.


Команда `http-log` принимает JSON с `current`, списком `references` и `policy_valid_until_s`. Каждая минута содержит `entity`, `cohort`, `start_s`, логический `complete` и `events`. Каждое событие содержит уникальный `id`, время завершения `time_s`, идентификатор `client` из доверенного прокси и финальный HTTP `status`. Включайте только клиентские запросы к приложению. Эталон составляют закрытые обычные минуты того же сервиса и той же когорты. HTTP-нагрузку считаем относительно медианного количества запросов, ошибки как долю 5xx. Без покрытия или ненулевого эталона часть метрик остаётся неизвестной.

    ./scripts/uv run --project ml python -m netwatch_ml.security_import http-log access.json > http.jsonl

Импортёры `packets` и `auth` также экспортируют строки наблюдателей, если передать `--cohort ingress-a --policy-valid-until "$EXPIRES"`. Для `packets` передайте `--destination` с адресом цели, когда `--entity` обозначает имя сервиса. По завершении минуты добавьте к измерениям строку доверенного календаря изменений и отправьте собранное наблюдение.

    cat probe.jsonl http.jsonl change.jsonl > minute.jsonl
    ./scripts/uv run --project ml python -m netwatch_ml.security_import --journal http://127.0.0.1:8080 telemetry minute.jsonl --entity lab-web --start "$START"

`make test-anomalies` ожидает свежий размеченный манифест с зафиксированными хешами правил, модели и входов. Для ранее использованного набора укажите в его отдельном манифесте `unseen_by_developers: false`, передайте `ANOMALY_MODE=--regression` и задайте отдельный `ANOMALY_REPORT`.
