# Классификация минутных наблюдений

Пятисекундный детектор TCP-сервиса продолжает работать через обычный журнал инцидентов. Для дополнительных источников есть отдельный классификатор. Он принимает одну проверенную минуту наблюдений за одним объектом. Результат доступен в CLI или через внутренний POST /v1/security/assess; в веб-журнал он автоматически не записывается.

Из корня NetWatch запустите:

    ./scripts/uv run --project ml python -m netwatch_ml.security_import observation minute.json

Пример содержимого minute.json:

    {"schema_version":1,"entity":"lab-web","start_s":0,"interval_s":60,"metrics":{"in_pps":150,"pps_baseline_ratio":6,"source_ips":20}}

Результат содержит packet_flood. Метод не сообщает о DDoS: неизвестно, был ли сервис недоступен. Поле findings содержит совпадения, unassessed перечисляет недостающие измерения. Пустой список совпадений при evaluated=0 означает, что ничего оценить не удалось. Несколько меток могут относиться к одному эпизоду.

| Источник | Какие признаки можно различить |
|---|---|
| Входящие пакеты и обычная нагрузка того же узла | Рост числа портов у одного источника, высокая частота пакетов, преобладание UDP или ICMP при всплеске |
| Пакеты и независимые пробы доступности | Перегрузка с отказами; множество видимых источников добавляет метку распределённой перегрузки |
| Счётчики рукопожатий TCP | Рост SYN при низкой доле завершений |
| Журнал HTTP-сервера | Распределённый всплеск с ошибками; длительное ожидание незавершённых заголовков с тайм-аутами |
| Журнал входов | Многократные отказы для одной учётной записи |
| ModSecurity с OWASP CRS | Сообщение WAF о признаках SQLi или XSS |
| Контроль передачи данных и политика назначения | Передача чувствительных данных за разрешённую границу |
| События процессов, связанные с запросом | Нарушение политики запуска процесса; возможная эксплуатация |
| Входной фильтр, монитор шлюза и проверка TLS | Нарушение политики адреса источника; смена шлюза вместе с несовпадением TLS-ключа |
| Журналы DNS и исходящих соединений | Возможный DNS-туннель по характеру имён; периодические соединения с неодобренным адресом |

## Подключение данных

Команда packets принимает два файла метаданных отдельных пакетов от Go-сенсора (replay без параметров хоста и сервиса). Укажите IP назначения, начала полной текущей и обычной минуты в секундах Unix:

    ./scripts/uv run --project ml python -m netwatch_ml.security_import packets current.jsonl --reference ordinary.jsonl --entity 192.0.2.10 --start 120 --reference-start 0 --complete-minutes

Флаг подтверждает проверку оператором длительности и отсутствия потерь, а не выполняет эту проверку. Нулевой знаменатель не заменяется единицей. Для режима waf вход — один JSON-аудит ModSecurity; --entity и --start оператор берёт из контекста этой транзакции. Результат относится к сообщениям одной транзакции.

Режимы auth, dns и egress читают JSONL (одна запись на событие). Нужны --entity, --start и --complete-minute. Обязательны время time_s в секундах Unix и entity. Для auth добавьте principal и логический success; для dns — qname и логический unapproved_destination; для egress — unapproved_destination и одну запись на начало исходящего соединения. В DNS-группе entity обозначает одну пару клиент/родительский домен, в egress — клиент/точное назначение. Метка неодобренного назначения поступает из вашей политики. Пример строки журнала входов:

    {"time_s":123,"entity":"lab-web","principal":"demo","success":false}

Для остальных источников передавайте сводку по [схеме](../contracts/security-observation.schema.json). Доли задаются от 0 до 1, отношения к обычной минуте — как множители, unavailable_fraction — доля неуспешных независимых проверок доступности. Пропускайте неизвестные значения. Измерения, относящиеся к разным узлам, запросам или периодам, нельзя объединять ради срабатывания.

[Пороговые правила](../ml/netwatch_ml/security.py) описывают наблюдаемое сочетание признаков. Это начальные пороги, не оценка вероятности атаки. Законная нагрузка может вызвать тот же сигнал; отсутствие сигнала не исключает атаку. CLI не устанавливает WAF, монитор процессов или датчик утечек. Для оценки точности нужны независимые размеченные эпизоды, обычная нагрузка и частота ложных инцидентов за час.
